# Ordinary image sizes and retained memory — October 13, 2026

macOS arm64, Oracle JDK 25, JAI 1.1.3. Two isolated native runs, one app at a time.
The JVM selected a 6 GiB maximum heap on this Mac; this is an observed launch
setting, not a product requirement or a proposed new cap. No exhaustion test.

## Ordinary workload and BUG-029

Create three centered images at 256×256: Uniform Noise (mean 0.5, half-width 0.5,
seed 17), Constant amplitude 3, and Cylinder radius 32. Apply Threshold 0.5 to
the noise, then multiply its result by the Constant. Inspect the output, export
source/threshold/product. Enlarge all three sources to 512×512 (noise seed 18,
constant 2, radius 64), then 1024×1024 (seed 19, constant 1.5, radius 128).
Inspect plots, histogram and profiles, export, then delete the five documents.

The first run stayed responsive but the result was wrong after enlargement.
The Constant generator inherited image padding and retained its original 256×256
extent. At 1024×1024 only 65,536 of 1,048,576 constant samples were nonzero.
Product differences affected 98,217 pixels at 512 and 491,995 at 1024. Every
threshold sample matched its noise input; every incorrect product matched the
old constant extent, isolating the defect from cache or random-seed changes.

Constant now generates its amplitude across the requested grid, following its
existing infinite-support definition. Four Cartesian/magnitude-phase and origin
regressions failed before and pass after; linked size mismatch/recovery and
amplitude edits are included. In the repeated native workload, nine exports
match every source, threshold and multiplication sample at all three sizes.
All 1,048,576 constant values at 1024 are 1.5 + 0i. A separate uncentered 512×256
constant is −2.5 + 0i everywhere; failed save → correct path → save → reopen save
and Cancel keeps data/menu behavior correct. Existing general image geometry
controls remain present; refining that presentation is outside this correction.

## Measurements

RSS sampled once per second; heap snapshots taken after each workload stage.
The three size checkpoints were not forced collections. Empty/live/deleted
histograms request collection. Interaction timings include CUA/AX observation
and are not operation benchmarks. Workflow elapsed time includes agent pauses.

| 256×256 | 71.4 | 425.9 |
| 512×512 | 184.2 | 554.7 |
| 1024×1024 | 493.0 | 1267.2 |

Overall sampled RSS peak, including exports and diagnostics: 1580.5 MiB before,
1411.6 MiB after. Live collected heap: 646.8 → 514.9 MiB. After deleting all test
documents and collecting: **618.2 → 484.8 MiB**. Both runs used the same source,
operation, resize, export and view sequence. This batch also changes Constant's
computation, so the memory difference is not attributed exclusively to cleanup.
One-second samples are not exact instantaneous peaks. This is a tested bounded
workload, not certification of arbitrary 1024 images, long chains, FFTs, the 4096
picker choice, or Windows. No crash/unresponsive phase was observed.

## Ownership evidence and BUG-030

A collected heap snapshot with an empty document list contained 11 real/imaginary
function objects and two operator systems. Read-only graph analysis found:

- A main-list renderer held its last deleted document through thumbnailProducer.
- Native JNI-local accessibility roots held disposed SaveComplexDialog buttons;
  each dialog still held its saved function/result.
- Other native accessibility roots held obsolete operation buttons and dimension
  combo boxes, whose listeners retained old editor/model graphs.

The renderer now drops a removed thumbnail without disturbing a live row, and
can paint empty. The failing last-row regression and surviving-row check pass.
A disposed complex-save dialog now drops its function reference. Native after
snapshots no longer show either ownership path. There are five real/imaginary
function objects and two systems remaining, six strongly reachable plus one
through a soft reference. The remaining strong paths begin at JNI-local native
accessibility roots. Do not describe this as complete document reclamation.

The diagnostic parses the documented [OpenJDK HPROF format](https://github.com/openjdk/jdk/blob/master/src/hotspot/share/services/heapDumper.cpp),
checks instance field sizes, and excludes Reference.referent from strong paths.
It identifies paths, not retained-size dominators. Full binary snapshots remain
only in /private/tmp; compact paths and class histograms are saved here.

## Open limitation: BUG-031

Native accessibility still retains obsolete editor controls during this audit.
The remaining 484.8 MiB is not explained solely by ordinary live documents, and
some reference paths are explicitly tied to macOS accessibility. Applicability
to manual use, other JDKs and Roger's Windows environment is unverified. Further
work should isolate native ownership and establish explicit editor cleanup;
it must not label all observed bytes a cross-platform application leak.

Full after package: **503 tests**, zero failures/errors/skips. No numerical
precision or rare-size work. Native logs are exception-free; the after run
includes the intentional, handled missing-folder save error. The first renderer
test was too strict when another live row was repainted; the final test explicitly
covers an empty last row and a surviving row, with recorded before/after runs.

Apps closed between builds and after checking; zero remaining processes verified.
Both memory samplers completed. No push/release. Next scoped batch: independently
check ordinary demonstration output; Windows and native accessibility retention
remain explicit gaps.
