## BUG-027: animation timers survive leaving or completing a demo

Source inspection found AnimatedPane lacked the Deconstructable callback used
by GUI.removeContent/setContent, and its completed-frame callback did not stop
the timer. Four regressions using actual 1D/2D convolution panels fail: leaving
a playing demo and reaching its last frame both leave a live timer.

The shared pane now implements the established cleanup contract and stops the
timer on completion. All four tests pass. Full package: **495 tests, zero
failures/errors/skips**. No numerical implementation or UI behavior was added.

Native before/after: create a 64×32 E image, open convolution with that input in
both slots, press Play, then select the source without pressing Stop. A bounded
JVM class histogram after collection contains one TimerQueue.DelayedTimer before
and none after. Reopening and play/stop remain usable after the correction.
Both snapshots still contain one Convolve2D object; complete panel reclamation
is not established and remains part of the memory-lifecycle gap. The correction
stops background work; do not infer a general memory-capacity guarantee.

Native logs contain no exceptions. Test apps closed between builds and after
verification, with zero remaining processes. Local commit only; no push/release.
