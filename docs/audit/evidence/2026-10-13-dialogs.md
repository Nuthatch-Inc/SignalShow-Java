# File cancellation and recovery — October 13, 2026

macOS arm64/JDK 25, one native SignalShow instance at a time. Ordinary 256×256
constant images, temporary test files, paths containing spaces. No user files
were overwritten. Automated typing and readback worked throughout this batch.

## Observations and correction

Cancel Save Complex Data and Load Complex Data, then continue editing: source
parameters remain intact. Cancelling a save targeting an existing test file
preserves its bytes. Explicitly saving over that file writes the new values.
The existing application does not request overwrite confirmation.

BUG-028 reproduced twice, including after a fresh launch: save complex data to a
missing folder, dismiss the File I/O Error, then save to a valid path. Both saves
close their dialogs, but after the successful retry every native menu is disabled.
The main editor still accepts typing. Raising the window does not restore menus.
The first successful recovery file contains the expected samples, so this is
not a failed typing check or a corrupt result.

ComplexIO swallowed write failures and opened its own error dialog owned by the
main frame; SaveComplexDialog always reported success and disposed itself.
Writers now propagate IOException and close resources on every exit. The save
dialog owns its error message and returns false on failure, retaining the path
for correction or cancellation. All repository callers use the updated contract.
No new product wording or controls were introduced. The native menu symptom is
verified here; no claim is made about a general JDK or Windows defect.

## Verification

- After correction, failed complex save → dismiss error leaves Save Complex Data
  open. Correct the path → save → save again: menus remain usable.
- Failed complex save → dismiss error → Cancel → open image export works.
- Cancel image export creates no file. Failed CSV export retains its dialog;
  correcting the path writes all 65,536 real values as 4. A subsequent complex
  save and Load/Cancel still work. This export path needed no code change.
- Change source amplitude from 4 to 6, Cancel a save targeting its existing file:
  saved samples remain 4. Save again explicitly: every real sample becomes 6;
  imaginary samples remain zero and menus are enabled.
- Five complex files and one CSV were checked at the cancellation checkpoint;
  the final overwrite is recorded separately with its new hash. No missing
  directory or cancelled export target was created.
- Two production 1D/2D failure→retry regressions plus five existing complex-file
  regressions pass. Full package: **497 tests**, zero failures/errors/skips.
  Native logs contain no exceptions. Dialog behavior is verified natively;
  headless tests alone do not certify modal behavior.

The initial CSV verifier incorrectly skipped each row's first value as if it
were a row label. Inspection confirmed this format has column headings only;
corrected parsing checks all 256×256 entries. No product numerical fix was needed.

Limits: native Windows recovery remains untested. Disk-full, interrupted writes,
network storage and atomic replacement are outside this batch. Existing saves
write directly to the selected path without a replacement confirmation.
Test app closed at completion; zero remaining processes verified. Local commit
only, no push or release.
