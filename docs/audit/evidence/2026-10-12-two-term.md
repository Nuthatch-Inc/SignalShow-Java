# Two-term image editing and arithmetic symbols — October 12, 2026

## Reproduction

Juliet observed the broken arithmetic symbol during the native audit. On the
421-test build, create a 256×256 zero-centered real image: Polar → Rectangle,
full width 64; Add; Cartesian → Gaussian. The plus slot became an image, the
rectangle returned to width 16, and selecting it displayed the Gaussian's
thumbnail. The library equation showed two rectangles instead of the authored
rectangle and Gaussian. This is the current reproduction of historical BUG-006;
the original cache hypothesis did not explain the parameter/model corruption.
A saved broken result remains in the isolated test folder as `two term before.txt`.

## Fix

`CreateFunctionPart2DPanel` gives each active term editor its own broadcaster and
forwards completed edits to the calculator. Removed editors are disconnected;
initial binding of both separable subterms cannot publish a partially bound
term. New terms are inserted before their editor is initialized. Calculator
updates also require a function-term slot, preserving operator icons and values.

`EditAnalyticFunctionTerm1DPanel` records the polar dimension for defaults when a
new generator is chosen. Changing image dimensions no longer reapplies a default
width over the value the user entered. No new controls or UI wording were added.
