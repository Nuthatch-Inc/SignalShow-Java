## BUG-043: complex powers discard input phase

Create a centered 128×64 Radial Complex Exponential: amplitude 1.2, radial center 3,
period 45, initial phase 35 degrees. Its magnitude is nonzero everywhere. In a new
system choose Exponent and set a=2, b=0; the output becomes constant real 1.44
instead of retaining the spatially doubled phase. Chain Invert and save source
and both results. Change a to .5 and save power/reciprocal. Through the source's
imaginary editor change amplitude .8, period 36, initial phase 55 degrees; save
source and square root. Change exponent b to .25; save power and reciprocal.

The source arrays are correct, but all seven operation outputs are wrong. The
square has maximum complex error 2.879995; other errors range 1.2637–2.6909. Every
wrong stage, hash and metric is retained separately in the before-failure record.
This failure affects ordinary squaring as well as fractional and complex powers.

ArrayMath.complexPower used logarithm(), a magnitude-only logarithm also used by
cepstrum, as though it were a complex logarithm. Its imaginary part is zero. The
power calculation now combines log-magnitude with the input phase. The separate
logarithm/cepstrum behavior is preserved. Both 1D and 2D Exponent callers share
this correction; Invert itself did not need a change.

Fourteen production regressions all fail before and pass after: square, square
root and .5+.25i power across 1D/2D and both origins; linked 2D reciprocal chains
after source/parameter edits. Expected values come from known authored polar data,
with an additional Cartesian square identity. Focused 56 and full 606 tests pass,
zero failures/errors/skips. Tests use ordinary finite nonzero complex inputs.
